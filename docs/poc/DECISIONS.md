- D15 (user request): On-screen controls follow the DS Lite: D-pad left of/below-left of the touch screen, X/Y/A/B diamond on the right (X top, Y left, A right, B bottom), Start/Select by the face buttons, L/R as shoulder pills at the clusters' outer top corners, Lid/Pause mirrored by the D-pad. The solver picks a bottom band (clusters under the screens) or flanking columns (clusters level with the lower screen), whichever keeps the screens largest; overlaying the screens is the last resort (`controlsOverlapScreens`). D-pad is 8-way with a dead zone; face buttons allow thumb rolling.
- D16: Audio pacing. The SPSC ring primes to ~60 ms before playing (and re-primes after running dry) instead of crackling on an empty ring. Emulation pacing runs up to ±0.5% off the core rate to hold ~60 ms queued, absorbing host/audio clock drift. A 150 ms ceiling bounds latency, but if output stays backed up for 250 ms the queue is dropped and the engine restarted, so emulation never freezes. A 1 s watchdog restarts the engine if the system stopped it. `audio_buffered_ms` is logged.
- D17 (V15): Microphone is hold-to-talk via an on-screen Mic pill mapped to the core's L3 mic button in "hold" mode, with the core's host-mic input fed by the libretro microphone interface in the bridge. Capture (`MicCapture`, separate AVAudioEngine) runs only while held, so the system mic indicator matches actual capture. Permission is requested on first press, never at launch; if denied, one message and the game reads silence. The audio session switches to play-and-record only once permission is granted.
- D18: Homebrew SD card (DLDI). It was silently disabled: the bridge never set `melonds_homebrew_sdcard`, which defaults to disabled. It is now enabled as a single per-game image (`CoreSaves/melonDS DS/dldi_sd_card.bin`) with host-folder sync off: melonDS exports the sync folder only on clean unload, so after an app kill a stale folder could overwrite newer image data. The core writes sectors through 64 KB-buffered stdio, so `duo_flush_storage` (`fflush`) runs at every save checkpoint and pause. The new image is sparse: 4 GB logical, about 700 KB on disk.
